# Architecture

## Contract

One Good Icon owns the specialist app-icon lifecycle. Its stable interface is three gated phases:

1. **Explore** turns real material into 4–6 distinct visual hypotheses and pauses for selection.
2. **Refine** develops one or two selected candidates, critiques them, tests them in size/context/platform conditions, and pauses for approval.
3. **Ship** chooses raster, vector, or useful layers; packages only requested platforms; and verifies actual files and configuration.

The human owns both gates. When MAYA is present, MAYA owns product-level visual direction and the durable design contract; One Good Icon supplies icon-specific evidence and artifacts.

## Information shape

`SKILL.md` contains the invariant sequence, gates, and reference routing. Each phase and platform adapter lives behind a conditional pointer. Source history is isolated from operational instructions so research detail does not consume every run.

## Extension boundary

A future platform adds one adapter reference describing inputs, transformations, configuration, validators, and fallbacks. It must not alter the three-phase contract or make a provider a core dependency.

## Non-goals for the MVP

- bundling or proxying an image-generation service;
- recreating visual explorations with frontend code;
- automatic aesthetic scoring;
- forcing vectors or layer separation onto artwork that does not benefit;
- claiming deterministic automation where a platform tool is unavailable.
